CrossCheck II: A Compiler Plugin for Certified Cost Bounds of Real-Time C and C++ Code, and its Evaluation

Luca Dall'Olio

cs.LO Nov 23, 2026 · v1 cs.PL cs.SE
verification tooling
Read PDF arXiv abstract Code
TL;DR
Cost certificates emitted by a Clang plugin are validated by a checker compiled from a Lean 4 definition proved sound, with mini-C semantics defined in Lean.
Abstract
We describe a plugin for the Clang compiler that bounds the cost of C and C++ functions intended for real-time use, and rejects at compile time the functions that allocate, throw, call through pointers, or contain a loop or a recursion for which no bound is found. Loops are bounded by affine ranking potentials synthesized with an SMT solver through Farkas' Lemma, or by logarithmic ones, recursion by depth and size potentials, and callees are analyzed in the calling context in which they are used. For functions in a linear fragment, the plugin emits a cost certificate that a checker, compiled from a Lean 4 definition proved sound in a companion paper, validates with integer arithmetic only; the bound then depends neither on the analyzer nor on the solver. On the 29 kernels of the TACLeBench collection, without annotations, the plugin bounds 142 of 220 loops in the calling contexts of the programs, 131 of them exactly as the benchmarks' flow facts, and 161 of the 165 bounded functions receive a certificate that the checker accepts, 152 of them also validated against an independent description of the source. On the CMSIS-DSP library for Cortex-M (786 functions), with assumed input ranges, it bounds 616 functions. We compare the loop bounds with loop counts observed by running the kernels and with five existing analyzers (LLVM's ScalarEvolution, KoAT2, CoFloCo, Infer and oRange), and the plugin with KoAT2 and CoFloCo on the C programs of the Termination and Complexity Competition: without annotations, 147 of 553 programs receive a certified bound that holds for all inputs, where the two tools bound 288 and 264. Loop bounds, exported annotations and the checker program are also tested on random programs and on mutated certificates.
Problem

Hard real-time C/C++ code needs bounds on loops and recursion, which are usually written by hand. Compilers do not check such bounds at compile time.

Approach

A Clang plugin rejects real-time functions that allocate, throw, call through pointers, or contain unbounded loops or recursion. Loops are bounded by affine ranking potentials synthesized with an SMT solver via Farkas' Lemma, or by logarithmic potentials, and recursion by depth and size potentials. For a linear fragment the plugin emits cost certificates, which a checker compiled from a Lean 4 definition proved sound validates using integer arithmetic only. A mini-C export, whose semantics is defined in Lean, enables translation validation against the source.

Results

On the 29 TACLeBench kernels the plugin bounds 142 of 220 loops in calling context, 131 of them exactly matching the benchmarks' flow facts. 161 of the 165 bounded functions receive certificates the checker accepts, and 616 of 786 CMSIS-DSP functions are bounded. On TermComp C programs it certifies 147 of 553, fewer than KoAT2 (288) and CoFloCo (264).
